# MediScan AI — Complete Starter Project

MediScan is a Flutter Android app with on-device OCR, medicine-label lookup, AI-assisted plain-language explanations, and English/Hindi text-to-speech.

## Important safety and scope
- This is an educational starter project, not a medical device.
- OCR can misread medicine names, strengths, batch numbers, and expiry dates. The app asks users to review extracted text.
- OpenFDA data is not comprehensive for medicines sold in India. A missing result does not mean a medicine is unsafe or unavailable.
- AI explanations are generated from supplied/retrieved text and can be wrong. They must not be used to choose a dose, change treatment, or replace a pharmacist/doctor.
- The app does **not** calculate dosage or certify that a medicine is genuine or unexpired.
- Never put an OpenAI API key in Flutter code. Keep it in the backend `.env`.

## Requirements
- Flutter stable SDK and Android Studio/Android SDK
- Python 3.11+ recommended
- An OpenAI API key for AI explanations (optional; lookup and OCR can be used without it)
- Internet access for medicine lookup and AI requests

## 1. Start the backend (Windows PowerShell)

```powershell
cd backend
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
Copy-Item .env.example .env
```

Edit `backend/.env` and add your key:
```env
OPENAI_API_KEY=your_key_here
OPENAI_MODEL=gpt-4.1-mini
```

The model name must be one available to your OpenAI API account. If you do not configure a key, the app can still perform OpenFDA lookup; AI explanations will return a clear configuration message.

Run the backend:
```powershell
uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

Check `http://127.0.0.1:8000/health` in a browser.

## 2. Generate native platform scaffolding

The Flutter UI and feature code are shared across Android and iOS. The ZIP intentionally avoids pinning old Gradle/Xcode project files; generate native scaffolding using the Flutter SDK installed on your machine.

Open a terminal in the `app` folder:
```powershell
flutter doctor
flutter create --platforms=android,ios .
flutter pub get
```

This generates/repairs the platform project files. After running it, verify that Android permissions from `android/README_ANDROID.md` and iOS permission descriptions from `ios/README_IOS.md` are present. Do not overwrite your `lib/` folder or `pubspec.yaml`.

### Android
Build and run on Android using Android Studio/emulator or a connected device.

### iOS
You can generate the iOS project files on Windows, but **building, signing, installing, and running an iOS app requires macOS with Xcode**. On a Mac, install Xcode and CocoaPods, then:
```bash
cd app
flutter doctor
flutter pub get
cd ios
pod install
cd ..
flutter run
```
Select an iOS Simulator or connected iPhone in Xcode/Flutter. For a physical iPhone, configure signing/team in Xcode under `ios/Runner.xcworkspace`.

## 3. Connect Flutter to the backend

Choose the right URL:
- Android emulator: `http://10.0.2.2:8000`
- iOS Simulator: `http://127.0.0.1:8000`
- Physical Android phone or iPhone: `http://YOUR_PC_LAN_IP:8000` (phone and PC must share Wi-Fi; allow port 8000 through Windows Firewall if needed)
- Production: use your deployed backend's HTTPS URL

For iOS local development, add the iOS usage-description keys in `ios/README_IOS.md` to `ios/Runner/Info.plist`. iOS App Transport Security can block plain HTTP; use HTTPS for production and configure local development networking intentionally rather than disabling security broadly.

Example for Android emulator:
```powershell
flutter run --dart-define=API_BASE_URL=http://10.0.2.2:8000
```

For a real phone, replace the URL with your computer's LAN IPv4 address:
```powershell
ipconfig
flutter run --dart-define=API_BASE_URL=http://192.168.1.5:8000
```
Use the actual IPv4 address from your PC; `192.168.1.5` is only an example.

## 4. Build Android and iOS

Android APK:
```powershell
flutter build apk --release --dart-define=API_BASE_URL=http://YOUR_PC_LAN_IP:8000
```

iOS Simulator / device build (run on macOS with Xcode):
```bash
flutter build ios --release --dart-define=API_BASE_URL=https://YOUR_DEPLOYED_BACKEND
```
An iOS release for distribution also requires Apple signing/provisioning. The backend must be reachable from the device. Prefer HTTPS for deployed services.

## Features
- Shared Flutter codebase targeting Android and iOS
- Take a photo or choose a medicine label image
- On-device OCR with Google ML Kit
- Review extracted text before search
- OpenFDA label lookup (availability varies by medicine)
- AI plain-language explanation from the retrieved label text
- English (India) / Hindi (India) text-to-speech
- Error/loading states and explicit safety notices

## Security notes before publishing
- Deploy backend behind HTTPS.
- Add authentication, rate limiting, request-size limits, monitoring, and privacy policy before public release.
- Do not log uploaded images or sensitive user data.
- Configure CORS to the exact client origins for a production deployment.
- The sample backend does not store images or user profiles.
